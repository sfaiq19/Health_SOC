# Healthcare SOC searches

Status: query definitions prepared; execution/results/screenshots pending the Wazuh lab.

Use Lucene query mode in Discover, not Wazuh API WQL. Replace `<RUN_ID>` with the actual opaque UUID and set the exact UTC interval. Check field mappings before aggregating. Archive fields below are proposed `data.*` fields verified against the application's schema, not yet observed in a live index.

| Query | Data view | Filter | Required output |
|---|---|---|---|
| Q1 | wazuh-archives-* | `data.service:"hospital-lab" AND data.run_id:"<RUN_ID>"` | Unique event IDs and counts by action/outcome |
| Q2 | wazuh-archives-* | `data.run_id:"<RUN_ID>" AND data.action:("login_failure" OR "login_success")` | Time, actor, outcome; failure count followed by success |
| Q3 | wazuh-archives-* | `data.run_id:"<RUN_ID>" AND data.action:"record_read" AND data.care_scope:"unassigned"` | Actor and distinct patient IDs; rate separately |
| Q4 | wazuh-alerts-* | `rule.groups:"syscheck" AND agent.name:"hospital-win"` | Exact run interval, canonical dummy directory, each affected path and old/new SHA-256 |
| Q5 | wazuh-archives-* | `data.run_id:"<RUN_ID>" AND data.action:"export_completed"` | Destination approval, numeric bytes, digest and transfer ID |
| Q6 | wazuh-alerts-* | `data.run_id:"<RUN_ID>" AND rule.id:(110101 OR 110102 OR 110103 OR 110201 OR 110301 OR 110302)` | Rule, severity, source time, processing time and actor |

For Q4 there is no application run ID: constrain agent, exact file set and UTC interval and reconcile digests against the two independent inventory requests. Never add an invented run ID to native FIM events.

Export query results and save the exact query/time bounds with screenshots in `query-results/`.
